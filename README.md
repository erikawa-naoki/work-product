# document-classification

## 規則
1. 1_0_preprocess.pyを必ず使うこと．また，それぞれpreprocess用のconfigを適切だと思う形で作成すること．小島はこれを使って実験・評価をします
2. 学習時，p4_0_compute_cost.pyを使って計算コストを計算すること．p1_0_sample_train.pyが参考になる．
3. 学習時およびテスト時，p4_0_output_train_result.pyで出力すること．これを使えば全員の出力の形式がそろう．p1_0_sample_train.pyが参考になる．
4. 推論だけを行うプログラムも作成すること．このとき，p4_0_compute_cost.pyで推論にかかる学習コストを計算すること．また，その出力はp4_0_output_infer_result.pyを使うこと．p1_0_sample_infer.pyが参考になる．
5. preprocessのコンフィグは，各手法に合わせたものを作成してもらうが，合わせられる部分は合わせてほしいので，コミュニケーションをとって調節すること．
6. LSTMとTransformerでは単語ベクトルを使うはず（少なくとも初期値として）．単語ベクトルは同じものを使用したいので，https://huggingface.co/facebook/fasttext-ja-vectors を使用すること．
7. .pyでコードを書くこと．colabで動かすときは，colab内でディレクトリ構造を作成し，.pyを呼び出すこと．
8. ファイル命名規則に従うこと．
9. 他の人が書いたプログラムは原則加工しない．やるならブランチを切ること．
10. 「どのような処理をしたか」と，「どのような結果になったか」を説明するドキュメントを作成すること．発表ではそのまま使わないので，理解が可能なら見やすさは問いません．
11. 少なくとも，全体の精度，各カテゴリのprecision, recall, f1, supportとconfusion matrix，学習曲線は出すこと．
12. 成果物はsrc/dataとsrc/resultの下に出力すること．colab上で出力するだけで終わらさず，ファイルとして残すこと．
13. 学習率や各層のノード数，乱数のseed，入力および出力先のディレクトリなどのパラメータはjson形式のconfigで管理すること．特に乱数のseedは実験の再現性を確保するため，必ず固定する機能を作成すること．
14. colabでの動作が厳しい場合（ランタイムはCPUではなくGPUを選ぶこと），小規模な実験で動作確認後，小島に依頼してください．特に2_4が無課金のcolabでは動かない可能性があります．所有しているGPU(Vram=12GB)で計算します．それでも動かなかったら，軽量化の検討を依頼します．BERT系なら軽量なモデルもあります．  
注文は多いが，LLMにこの.mdを食わせれば簡単に対応してくれるはず...

### ファイル命名規則
2_1: ナイーブベイズ関連  
2_2: LSTM関連  
2_3: Transformer関連  
2_4: 事前学習済みモデル関連  
上のようなタグをつけて，何に関連しているかを示す．  
srcなど，共有するディレクトリ直下はファイル名に付与．  
resultなど，人によっては複数ファイルに分かれそうなディレクトリにはディレクトリ名にタグをつける  
小島の1_0_preprocess.ipynbを動作させたらわかるはず  
.pyファイルは数字から始まると不都合があるので頭にpを付ける．
例：p1_0_sample_train.py


## ディレクトリ構造
git上では見ずらくて申し訳ない．エディタ上で確認してください．  
.  
├── docs        --- ドキュメント．複数人で編集するならgoogleDriveにおいた方がよい．    
├── colab       --- ipynbファイル    
└── src         --- ipynb以外のプログラム．.pyプログラムで書いてipynbで呼び出してほしい．    
    ├── data    --- ここに学習用データを保存．容量の問題でgitでは共有しない．dataの下に自分用のディレクトリを作成し，そこに出力するようにしてほしい．    
    ├── configs --- json形式のコンフィグ    
    └── result  --- ここに学習結果,モデル，中間生成物を保存．容量の問題でgitでは共有しない．dataの下に自分用のディレクトリを作成し，そこに出力するようにしてほしい．
